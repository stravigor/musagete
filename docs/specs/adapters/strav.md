## 1. Pipeline step map

`@strav/cli ^0.4.11` exposes **bulk schema-driven generators**. Schemas are hand-written; one command per phase regenerates *every* model or *every* API artifact from those schemas. Existing files are skipped by default to protect hand-edits — pass `--force` to overwrite. Custom logic that must survive regeneration should live in *separate* hand-written files alongside the generated ones; the generators are idempotent, the overrides are not regenerated.

Output paths come from `config/generators.ts` (defaults shown below; override per project if needed).

| #  | Generic step            | Strav step                                                                                  | File location (default)                                                                                       | Hand-written or generated? |
|----|-------------------------|---------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|----------------------------|
| 1  | Data-shape sketch       | Strav schema definition                                                                      | `database/schemas/<name>.ts`                                                                                   | hand-written               |
| 2  | Migration               | Diff schema vs. db, write migration files                                                    | `database/migrations/<ts>_<message>/`                                                                          | generated by `generate:migration` |
| 3  | Apply migration         | Run pending migrations                                                                       | n/a                                                                                                            | command (`migrate`)        |
| 4  | Models + enums          | Bulk regen from all schemas                                                                  | `app/models/<entity>.ts`, `app/enums/<entity>.ts`, plus barrel `index.ts`                                       | generated by `generate:models` |
| 5  | API surface (bulk)      | Events + validators + policies + services + controllers + routes regenerated from schemas    | `app/events/`, `app/validators/`, `app/policies/`, `app/services/`, `app/http/controllers/`, `start/api_routes.ts` | generated by `generate:api` |
| 6  | Policy logic            | Authz / RLS rules filled into the generated policy class                                     | `app/policies/<entity>_policy.ts`                                                                              | hand-written into the generated stub |
| 7  | Service overrides       | Custom orchestration / business logic that must survive regeneration                         | `app/services/<entity>_<override>.ts` (a *separate* file from the generated `<entity>_service.ts`)             | hand-written               |
| 8  | Background job          | `@strav/queue` job (no generator)                                                            | `app/jobs/<name>.job.ts`                                                                                       | hand-written               |
| 9  | Seeder                  | Database seeder class                                                                        | `database/seeders/<name>_seeder.ts`                                                                            | generated by `generate:seeder <name>` |
| 10 | CLI command (per-project) | Subcommand exporting `register(program)`, auto-discovered                                  | `commands/<name>.ts`                                                                                           | hand-written (see §10)     |
| 11 | Test                    | BDD tests via `@strav/testing`                                                               | `tests/<slice>/<name>.test.ts`, plus `tests/api/` for generated API tests                                       | hand-written (slice tests); generated (API tests) |

Hand-written endpoint tail (when `generate:api` cannot model the surface — bespoke flows like auth, AI streaming, search palette, custom workflows). Slices that ship endpoints with no schema source register them here:

| #  | Generic step             | Strav step                                                                | File location                                                                                                | Hand-written or generated? |
|----|--------------------------|---------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|----------------------------|
| 5a | Hand-written controller  | Bespoke action surface (no schema source)                                  | `app/http/controllers/<name>_controller.ts`                                                                   | hand-written               |
| 5b | Hand-written route file  | Programmatic route registration for a per-area surface                     | `routes/<area>.ts`, mounted from `start/`                                                                     | hand-written               |
| 5c | Hand-written service      | Domain logic for the bespoke flow (auth state machines, AI streaming, …)  | `app/services/<area>/<name>.ts`                                                                                | hand-written               |
| 5d | Hand-written policy       | Authz for the bespoke flow if no `app/policies/<entity>_policy.ts` exists | `app/policies/<area>_policy.ts`                                                                                | hand-written               |

UI tail (Strav-specific — server-rendered template + Vue island):

| #  | Generic step           | Strav step                                  | File location                                              | Hand-written or generated? |
|----|------------------------|---------------------------------------------|------------------------------------------------------------|----------------------------|
| 12 | View / template        | `.strav` server-rendered template            | `resources/views/<area>/<name>.strav`                      | hand-written               |
| 13 | UI component (island)  | Vue 3 SFC mounted as an island               | `resources/islands/<Name>.vue`                             | hand-written               |
| 14 | Style                  | CSS Module (or vanilla-extract opt-in)       | `resources/islands/<Name>.module.css`                      | hand-written               |
| 15 | Token import           | Global CSS via `@layer tokens`               | `resources/css/tokens.css` (loaded once in root template)  | hand-written               |

AI / RAG tail (when a slice ships AI features):

| #  | Generic step           | Strav step                                  | File location                                   | Hand-written or generated? |
|----|------------------------|---------------------------------------------|-------------------------------------------------|----------------------------|
| 16 | AI tool                | `@strav/brain` tool                          | `app/services/ai/tools/<name>.tool.ts`          | hand-written               |
| 17 | AI agent               | `@strav/brain` agent                         | `app/services/ai/agents/<name>.agent.ts`        | hand-written; tool allowlist explicit |

Per-project commands — including one-off jobs like reindexing, backfilling, or cleanup — live in `commands/<name>.ts` (§10). A registered command gets `--help`, option parsing, auto-discovery, and a single canonical invocation surface (`bun strav <name>`).

## 2. Checkpoint placement

AGON's Build Turn has three mandatory stop-and-confirm checkpoints. They land on:

| Checkpoint | Lands after step | What the human acks |
|------------|------------------|---------------------|
| **1** | Step 1 — schema definition committed and migration generated | Resource shape, fields, boundary (platform vs. tenant), RLS classification, migration content |
| **2** | Step 6 — policy logic filled into the generated stub | Authz / RLS logic matches Tech Spec's *Policy & invariants*; RLS policy registered for the new tenant tables |
| **3** | Step 11 — first failing BDD test draft | Test encodes the acceptance criterion before any production code beyond generation |

## 3. Generator commands

**Invocation.** Commands are invoked as `bun strav <command>`. Bun resolves to the project's `strav.ts` at the repo root, which re-exports the `@strav/cli` entry — that, in turn, auto-discovers commands from `@strav/cli`'s built-ins, every installed `@strav/*` package's declared `strav.commands` directory, and the project's own `commands/` directory.

Each generator produces "one file" under AGON batching Rule 3, regardless of how many files are emitted.

```sh
# 1. After hand-writing or editing schemas under database/schemas/,
#    generate the next migration by diffing schemas vs. live database state.
#    -m / --message names the migration directory's commit-style message.
bun strav generate:migration -m "<message>"
#   alias: bun strav migration:generate
#   alias: bun strav g:migration

# 2. Apply all pending migrations (grouped into a new batch).
bun strav migrate
#   alias: bun strav migration:run

# 3. Compare schemas with the live database without writing a migration.
#    Useful between checkpoint 1 and the next generate:migration to confirm
#    the diff is what you expect.
bun strav compare
#   alias: bun strav migration:compare

# 4. (Re-)generate model classes and enums from every schema.
#    By default, existing files are skipped to protect hand-edits;
#    pass --force to overwrite. No DB connection required.
bun strav generate:models [--force]
#   alias: bun strav g:models

# 5. (Re-)generate the API surface — events, validators, policies,
#    services, controllers, and route wiring — from every schema.
#    Same skip/--force semantics as generate:models. No DB connection required.
bun strav generate:api [--force]
#   alias: bun strav g:api

# 6. Generate a database seeder class skeleton under database/seeders/.
bun strav generate:seeder <name> [--force]
#   alias: bun strav g:seeder

# 7. Generate or refresh APP_KEY in .env (one-time, on first run).
bun strav generate:key [--force]
#   alias: bun strav g:key

# 8. Seed the database (chains sub-seeders via DatabaseSeeder.call()).
bun strav seed [--class <name>]
#   alias: bun strav db:seed

# 9. Run the dev server with hot reload.
bun run dev
#   equivalent: bun --hot index.ts
```

Schemas and jobs are hand-written under `database/schemas/` and `app/jobs/`; models, services, controllers, policies, validators, events, and routes are bulk-regenerated from schemas via the `generate:*` commands above.

If a generator is renamed in a later `@strav/cli` version, amend this file with the rename and link the Build Turn that surfaced the change.

## 5. Destructive commands — AI must never run

```sh
# Generic (always)
git push --force
git reset --hard
git branch -D
rm -rf

# SQL (always)
DROP TABLE
DELETE FROM ... (no WHERE)

# Strav-specific (always)
bun strav fresh                  # alias: migration:fresh — drops + rebuilds DB
                                 # (gated by APP_ENV=local + 6-digit confirmation)
bun strav rollback               # rolls back the most recent batch
bun strav rollback --batch <n>   # rolls back a specific batch (still destructive)
bun strav seed --fresh           # drops all tables, re-migrates, then seeds (destructive;
                                 # also gated by APP_ENV=local)
bun strav tenant:delete <id>     # cascade-deletes a tenant and every row scoped to it
```

The AI may *describe* these commands but never run them.

## 6. Slice-file framework extensions

Slice headers may add the following YAML fields when this adapter is in effect:

```yaml
# Optional — fill when meaningful for the slice:
resource_type:   Entity | Component | Attribute | Association | Event | Reference | Configuration | Contribution
tenancy:         platform | tenant
runtime:         api | web | job | island
strav_packages:  [@strav/http, @strav/database, @strav/brain, ...]   # used by this slice
```

If a slice introduces no new resource (e.g., a UI-only refinement), `resource_type` is omitted.

## 7. Framework-specific patterns

- **AI tool-restricted agent** — agent declares a single output tool that takes structured citations + answer; free-form text replies are not in the agent's surface. First instance: slice 005 Ask-the-KB. Re-noted in slice 006 review summary.
- **Vue island with server-streamed AI calls** — island POSTs to a controller that opens an `@strav/brain` agent, streams partial output back via chunked response (or SSE-over-fetch) which the island applies to local state. First instance: slice 004 slash commands.
- **RLS-aware service** — service functions take the current `(workspace_id, user_id)` from request context and never accept them as user-supplied parameters; the underlying `@strav/database` policy enforces tenancy at the SQL layer. First instance: slice 002 spaces.

---

## 8. Boundaries and tenancy

- **Boundary types:** `platform` (cross-workspace identity, sessions, OAuth) vs. `tenant` (everything else; carries `workspace_id`).
- **Slicing rule:** a single slice does not span both sides of the boundary. The auth slice (001) is platform-only; from slice 002 onward, all data is tenant. If a future capability needs both sides (e.g., a cross-workspace search), it decomposes into two slices.
- **Policy default:** authorization on tenant tables is enforced by Postgres RLS via `@strav/database` policy registration; controllers add per-action role checks (e.g., "writer or above"). Cross-tenant reads are *forbidden by the database*, not just by the controller.

## 9. Build Turn self-check

- [ ] Schema file committed at `database/schemas/<name>.ts`.
- [ ] Migration generated via `bun strav generate:migration -m "<message>"` and applied via `bun strav migrate`; schema diff matches the slice Tech Spec's data-model section.
- [ ] Models regenerated via `bun strav generate:models` (with `--force` if intentional); mixins (e.g., `searchable()`) attached as required.
- [ ] API surface regenerated via `bun strav generate:api` (with `--force` if intentional); generated events / validators / policies / services / controllers / routes reviewed as a whole.
- [ ] Policy logic filled into the generated `app/policies/<entity>_policy.ts` and matches Tech Spec's *Policy & invariants*; RLS policy registered for the new tenant tables.
- [ ] Every BDD scenario has a corresponding test file under `tests/`.
- [ ] If the slice ships a Vue island, it lives at `resources/islands/<Name>.vue`, mounts from the slice's `.strav` template, and uses CSS Modules.
- [ ] If the slice ships AI: agent file declares an explicit tool allowlist; tools are registered; `ai_calls` audit row written per call.
- [ ] If the slice introduces a custom CLI command, it lives in `commands/<name>.ts`, exports `register(program)`, and chooses `bootstrap()` vs `withProviders([...])` per §10.
- [ ] If the slice changes search-index shape: a reindex command (custom `commands/<name>.ts` or app-level) is documented and run.
- [ ] No files touched outside the slice (batching Rule 5).
- [ ] Slice file updated: `status: built`, `owner_turn: Build-TN`.
- [ ] `bun test` exits 0 globally.

## 10. Custom commands

**Every per-project command lives in `commands/<name>.ts` at the repo root.** Each file exports a single `register(program)` function that registers a Commander subcommand. The `@strav/cli` runner (invoked by `bun strav`) auto-discovers the directory at startup — no manifest, no registration boilerplate, no `start/` wiring.

One-off jobs (re-indexing, backfilling, ingest, ad-hoc cleanup) are commands too — registering them gives `--help`, option parsing, and a single canonical invocation surface.

### File shape

```ts
// commands/<name>.ts
import type { Command } from 'commander'

export function register(program: Command): void {
  program
    .command('<name>')
    .description('<one-line description>')
    .option('-x, --example <value>', 'Description of the option', 'default')
    .action(async ({ example }) => {
      // …command logic…
    })
}
```

The exported name is exactly `register`. The `Command` type comes from `commander`. `bun strav <name>` then runs the action; `bun strav <name> --help` shows the registered description and options.

### Bootstrap inside the action

Pick based on what the action actually needs:

| Need | Use |
|------|-----|
| Migrations, schema diff, model/API generation, raw model CRUD on the database | `bootstrap()` from `@strav/cli` (DB-only) |
| Anything that calls a provider-bound facade — `rag`, `mail`, `notification`, `auth`, queue dispatch, broadcast | `withProviders([…])` from `@strav/cli` |

```ts
// commands/db_health.ts — DB-only example (bootstrap)
import { bootstrap, shutdown } from '@strav/cli'
import type { Command } from 'commander'

export function register(program: Command): void {
  program
    .command('db:health')
    .description('Quick connectivity + schema-drift report')
    .action(async () => {
      let db
      try {
        const { db: database, registry, introspector } = await bootstrap()
        db = database
        // …work with registry / introspector…
      } finally {
        if (db) await shutdown(db)
      }
    })
}
```

```ts
// commands/rag_reindex.ts — facade-using example (withProviders)
import { withProviders } from '@strav/cli'
import { ConfigProvider, DatabaseProvider } from '@strav/kernel'
import { BrainProvider } from '@strav/brain'
import { RagProvider, rag } from '@strav/rag'
import type { Command } from 'commander'

export function register(program: Command): void {
  program
    .command('rag:reindex')
    .description('Recompute embeddings for every revision in a workspace')
    .requiredOption('-w, --workspace <slug>', 'Target workspace slug')
    .action(async ({ workspace }) => {
      const app = await withProviders([
        new ConfigProvider(),
        new DatabaseProvider(),
        new BrainProvider(),
        new RagProvider(),
      ])
      try {
        // …call rag.ingest / rag.flush / etc…
      } finally {
        await app.shutdown()
      }
    })
}
```

Pass only the providers the command actually needs — skipping `HttpProvider`/`ViewProvider` lets the command run while the dev server still holds port 3000.

### Project-shipped commands expected by this spec

Slices in this project that introduce a long-running or admin operation register a command rather than a script:

- **slice 005 / 007** — `commands/rag_reindex.ts` — recompute embeddings for a workspace after embedding-model or chunker changes.
- **slice 005** — `commands/search_reindex.ts` — re-push every doc through `@strav/search` after analyzer or schema changes.
- **slice 007** — the embedding/tagging job runs under `bun strav queue:work` (no extra command needed); `commands/queue_status.ts` may register a small read-only inspection command if useful.

When a slice introduces a new command, name it in the slice's Tech Spec under *Interface contract* (kind = `CLI command`).
